# Tool Comparison Feature Definitions

The tool comparison matrix was scored using three support levels. Full support denotes a feature that is directly available in the tool or in its documented primary workflow. Limited support denotes a feature that is available only with relevant restrictions, such as format constraints, dependence on an external service or viewer, partial coverage by a wrapper, or manual post-processing. No support denotes that the feature was not available or was not sufficiently documented for the tool under the definition used here.

The evaluated features were defined as follows:

- Standard model format input (SBML / JSON): the ability to import a genome-scale or pathway-scale metabolic model from a standard exchange representation, such as SBML, COBRA-style JSON, or a documented compatible model representation used by the tool. Support was counted as full when the model could be loaded through the tool's primary workflow without rebuilding the network manually. Support was counted as limited when the accepted input was restricted to a specific model source, model version, or conversion path.

- Pathway / subsystem-level visualization: the ability to visualize a selected pathway, subsystem, or biologically meaningful subnetwork rather than only an undifferentiated whole-model graph. Full support indicates that pathway- or subsystem-focused views are part of the intended workflow. Limited support indicates that the tool can display a relevant subnetwork, but the view is based on generic graph extraction or flux paths rather than explicit pathway or subsystem semantics.

- Flux data overlay: the ability to display reaction fluxes, flux variability, flux activity, or flux-derived reaction weights directly on the metabolic map or graph. Full support indicates that quantitative or categorical flux data can be mapped to reactions in the visualization. Limited support indicates that the tool visualizes only a narrower flux-related state, such as active/blocked reactions or flux variability classes, rather than arbitrary user-provided flux values.

- Web-browser map interface: the ability to view and interact with the metabolic map in a web browser or browser-rendered HTML/JavaScript interface. Desktop applications and desktop plugins, including Cytoscape- or Java-based workflows, were not counted as browser-based. Limited support was used when a tool can generate an HTML map for browser viewing, but the browser interface is provided through a dependent viewer rather than as the tool's own interactive application.

- Static map export (SVG / PNG / PDF): the ability to export the rendered map in static image or document formats suitable for figures, such as SVG, PNG, JPEG, TIFF, or PDF. Full support indicates that such export is available directly from the tool interface or documented workflow. Limited support indicates that static output is possible only through a host platform, browser capture, downstream viewer, or manual post-processing.

- Offline / local execution: the ability to run the core map visualization or map-generation workflow on a local machine without relying on a hosted web service during execution. Full support indicates that the core workflow can be installed and executed locally. Limited support indicates that local execution is possible but depends on online resources, hosted rendering, external databases, or partially local components.

- Programmatic access: the presence of a documented non-GUI route for reproducible map-related workflows, such as an API, scripting interface, package, command-line entry point, or plugin that can be called from code. Full support indicates that the programmatic interface covers the relevant map construction, visualization, export, or integration workflow. Limited support indicates that programmatic access exists but is incomplete relative to the GUI, mainly wraps an interactive viewer, exposes internal endpoints rather than a stable user-facing API, or requires substantial manual intervention.

- Automatic map generation: the ability to automatically construct a visual metabolic map or graph from model, pathway, reaction, or flux input without manual placement of every reaction. Full support indicates a documented automatic layout or map-generation workflow. Limited support indicates that automatic generation is available only within a restricted model database, pathway set, or template-driven workflow. Tools that primarily load or edit existing maps manually were not counted as supporting automatic map generation.

- Native Escher-compatible JSON output: the ability to produce or save map files in the Escher map JSON format, preserving the layout and reaction/metabolite mapping needed for downstream use in Escher-compatible viewers. Full support indicates direct Escher-compatible JSON output. Other JSON exports were not counted unless they followed the Escher map schema.
